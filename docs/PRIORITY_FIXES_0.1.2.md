# 0.1.2 优先缺陷修复（2026-10-28）

本轮只修改源码、测试、构建与发布文件，没有安装、启动或调试连接的鸿蒙设备。

| 项目 | 处理结果 |
|---|---|
| STO-01 | 本地文件缺失的书返回 `missingFile` 状态，不影响其他书；书架提示重新导入，可按原文件哈希恢复文件、位置、书签和云端版本，也可直接移除记录。缺失书不会上传同步。 |
| STO-02 | 数据库打开错误或阻塞后清除缓存，允许重试；被放弃的请求若延迟成功立即关闭连接；版本变化或连接意外关闭后清除句柄及文件缓存。界面增加“重试加载书架”。 |
| READ-01 / READ-04 | 改为全文字符串和每 1024 个码点的稀疏 UTF-16 索引，保留旧版 Unicode 码点定位协议；只切片当前页，搜索直接定位原字符串；章节扫描不再全文分行或创建字符数组。 |
| SYNC-01 | 未决冲突按书籍暂停同步，其他书继续；保留已显示的冲突，用户选择后恢复同步。 |
| 连续翻页 | 移除动画类后等待 Vue 更新落地，再读取布局并启动动画；作废的快照不会恢复旧动画；翻页准备期间避免重叠渲染。 |

数据库版本保持 v2，未清空或重建书架。原来的 SHA-256 文件身份、TXT 码点定位和云端协议保持兼容。

## 验证

- 36 项自动测试通过，包含迁移及二进制保留、缺失文件恢复、数据库失败/阻塞/版本变化重试、暂停与恢复同步、Unicode 跨索引块映射、搜索回绕、30 MiB 文本尾部导航，以及 Vue 动画更新顺序。
- 共享前端通过 TypeScript 检查及生产构建。
- macOS 原生编译及临时签名通过；HarmonyOS 编译及本地设备调试签名通过。自动测试不等于真机运行验证。

可复现的文本测量：`node --expose-gc scripts/benchmark-text.mjs`，生成 `build/reports/text-performance.json`。

本机 Apple Silicon / Node v24.20.0 下，生成的 30 MiB 中文含补充平面字符样例：

- 约 1,064 万码点，稀疏索引 43,484 字节。
- 解码约 18 ms，索引约 12 ms，章节扫描约 24 ms，未命中全文搜索约 1 ms。
- 30 MiB ASCII 样例约 3,146 万码点，索引 122,880 字节；索引约 38 ms，章节扫描约 44 ms。

这些是桌面 Node 的核心处理观察，不包含 WebView 排版、原生文件选择、数据库写入或手机运行；内存增量也不是严格峰值测量。仍保留 30 MB 文件检查，但不把本次测量表述为鸿蒙设备性能保证。

## 原清单中需要区别的结论

- READ-02 的 12,000 码点上限限制的是每页搜索范围，下一页从当前 `end` 接续，不会因此漏掉文字。
- IMP-01 中读取和 SHA-256 接口是异步的，不能仅凭调用位置断言“哈希阻塞主线程”；重复读取与导入性能不在本轮已解决项中。
- CLOUD-01 的门户 CORS 状态、HARM-01 的二进制字符集影响仍未验证。
- README 的签名安装状态已经更正；0.1.2 版本号在共享包与两端配置中统一。
