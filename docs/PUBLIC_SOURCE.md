# 源码发布与本机配置

源码导出采用明确的目录清单。执行 `node scripts/export-public-source.mjs` 后，得到 `build/github/leaf-reader`；`node scripts/audit-public-source.mjs` 可再次检查。

不会导出 Azure 登录缓存、个人阅读空间连接配置、部署报告、阅读数据库、签名配置、证书/私钥、设备安装包、构建输出、编辑器缓存或系统隐藏文件。鸿蒙仅提供无签名配置的模板，构建时可以复制为本机 build-profile。原工作目录中的私人配置保留，避免破坏本机同步和调试。

公开文档使用示例服务地址。运行者需自行部署 Azure、生成同步连接码，并为自己的鸿蒙设备配置签名。源码中不包含可直接访问任何个人书库的服务凭据。

审计会将导出文件与本机已知凭据值、服务主机名、个人主目录及账号标识进行比对，并检查常见私钥/访问令牌格式。审计失败会中止导出。该机制是发布前检查，不代替 GitHub 的后续凭据扫描和人工审查。

Git 提交应使用公开的 GitHub 用户名和 GitHub noreply 邮箱，避免将私人邮箱写入提交元数据。不要将原开发目录整体打包上传，也不要把 `.cache` 或设备专用签名包作为源码附件。
